# Service Desk SLA & Dispatch Analyzer

A small Python tool that turns a help desk ticket export into a daily operations report: what needs
attention right now, how the team is doing against SLA, how work is spread across technicians, and
which problems keep recurring. No third-party packages required (Python 3.9+).

## Run it

    python generate_sample.py                          # creates tickets.csv with 180 fake tickets
    python analyzer.py tickets.csv --now "2026-09-18 16:00"
    open report.html                                   # same report, formatted for sharing

Leave off `--now` when using a live export; it is only there so the sample data gives the same result every time.

## What it reports

| Section | Question it answers |
|---|---|
| Action queue | Which open tickets are breached, at risk (75%+ of SLA used), or unassigned? Sorted worst first. |
| SLA by priority | Are we hitting resolution targets for Critical / High / Medium / Low? |
| SLA by client | Which clients are getting the worst service? |
| Technician workload | Who is overloaded, and how many tickets have no owner? |
| Top recurring issues | What should be fixed at the root instead of ticket by ticket? |

## Using a real export

Export tickets from your PSA/ticketing tool (Autotask, ConnectWise, etc.) to CSV with these columns:
`ticket_number, client, title, priority, status, assigned_to, created, completed`
Dates use `YYYY-MM-DD HH:MM`; leave `completed` blank for open tickets. Rename columns in the export
or in `load()` to match. SLA targets are set in `SLA_HOURS` at the top of `analyzer.py`.

## How it works (the 2-minute explanation)

1. `load()` reads the CSV and converts the date text into real dates.
2. `analyze()` computes each ticket's age in hours (created to completed, or created to now if still open)
   and compares it with the SLA target for its priority. Over target = breached.
3. Open tickets are flagged BREACHED, AT RISK, or UNASSIGNED and sorted so the worst is on top.
4. Closed tickets are grouped by priority and by client to get % of tickets that met SLA.
5. `print_report()` prints to the terminal; `write_html()` writes the shareable version.

## Ideas to extend it

- Count business hours only (8-5, Mon-Fri) instead of clock hours.
- Pull tickets from the Autotask REST API instead of a CSV.
- Email the action queue to the dispatcher every morning.
- Track SLA % week over week to show a trend.

All data in `tickets.csv` is fake and generated by `generate_sample.py`.
